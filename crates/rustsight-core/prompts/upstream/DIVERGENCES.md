# Deliberate divergences from upstream prompts (tag v1.1.0)

The Rust builders in `crates/rustsight-core/src/prompts/upstream/` are held to
byte-for-byte output parity with the vendored sources under
`prompts/upstream/v1.1.0/` (pinned by `tests/upstream_prompt_parity.rs` with
fixtures generated by `scripts/prompt-goldens`). This file records every place
the *engine* intentionally deviates from upstream, and what was not ported.

## Ported with byte parity

- **Retain / fact extraction** — `build_extraction_system_prompt` (concise /
  verbose / verbatim / custom modes, language section, causal section,
  entity-labels section incl. map groups, optional-dimensions swap, output
  language directive), `retain_mission_preamble`, `build_chunk_user_message`
  (chunk index/total, event date, context, metadata, narrator, attachment
  section), `infer_temporal_date`, brace escaping.
- **Consolidation** — `build_consolidation_system_prompt`,
  `build_mission_section`, `build_consolidation_input`.
- **Reflect** — `build_system_prompt_for_tools` (full branch matrix:
  mental-models/observations/recall levels, budgets, directives, disposition,
  context, answer-ready, document mode), `build_agent_user_prompt`,
  `build_final_system_prompt`, directives sections, disposition description,
  `bank_name_line` / `bank_disposition_line`.
- **Shared** — `prompt_utils` (escape, language section/directive, context
  truncation cap).

## Engine divergences (production behavior)

1. **Extraction JSON envelope addendum.** Upstream hands the model a
   structured-output response schema (Pydantic → JSON schema). rustsight's
   OpenAI-compat provider uses JSON mode only, so the engine-facing wrapper
   (`prompts::extraction::build_extraction_messages`) appends an `OUTPUT:`
   section stating the exact `{"facts":[...]}` envelope after the
   byte-parity system prompt.
2. **Lenient extraction parsing.** `parse_extraction` accepts upstream's
   schema *and* rustsight's legacy schema (`text` key, `fact_type:
   "experience"`, entities as `{name, etype}` objects, `causal[].fact_index`)
   so existing scripted tests and older providers keep working. Unlike
   upstream, explicitly returned `occurred_start`/`occurred_end` are honored
   regardless of `fact_kind` (upstream drops them for conversation facts);
   the relative-date inference remains event-only, as upstream.
3. **Extraction storage format.** Upstream stores `what | When: X |
   Involving: Y | why` combined text and entity strings without types;
   rustsight keeps its `ExtractedFact`/`ExtractedEntity` types (etype
   defaults to `other` for plain-string entities) so entity resolution and
   the storage layer are unchanged.
4. **Consolidation pipeline keeps its own prompt.** The upstream builders are
   ported and parity-tested, but `engine/consolidate.rs` still sends
   rustsight's original `OBJECTIVE OBSERVER SYNTHESIS ENGINE` prompt and
   parses `{"observations": [...]}`. Adopting the upstream prompt requires
   porting its creates/updates/deletes response machine plus the
   facts/observations *formatters* from upstream's `consolidator.py` (not in
   the vendored set) — future ticket.
5. **Reflect pipeline keeps its own tool loop.** `build_system_prompt_for_tools`
   is ported with full branch parity, but the engine still exposes its
   `recall`/`read_observation`/`finish` tools and its own (diverged) system
   prompt: sending the upstream prompt as-is would advertise
   `search_mental_models`/`search_observations`/`expand`/`done`/`answer_ready`
   — exactly the hallucinated-tool-call failure upstream's own #1724 fixed by
   matching prompt to exposed tools. Adoption belongs with the mental-model
   retrieval ladder (RS-8).
6. **Parameterized clock.** Upstream builders read the wall clock internally
   (`_current_utc_datetime`, minute precision for prompt caching); the Rust
   builders take `current_datetime: &str` so tests are deterministic. Rendered
   text is identical for identical timestamps.

## Not ported (no parity claim)

- `reflect/prompts.py`: `build_final_prompt`, `build_done_request_prompt`,
  `split_context_history` + budget packing, `build_reduce_prompt` /
  `CLAIMS_SYSTEM_PROMPT` (split synthesis), `ROUND_SEARCH_QUERY_SYSTEM_PROMPT`,
  `STRUCTURED_DELTA_SYSTEM_PROMPT` / `build_structured_delta_prompt`,
  `STRUCTURED_RETRACTION_SYSTEM_PROMPT` / `build_structured_retraction_prompt`,
  `DELTA_SYSTEM_PROMPT`, `build_mental_model_refresh_context`,
  `_bank_identity_section`, `_length_directive`, `FINAL_SYSTEM_PROMPT`.
- `reflect/tools.py` / `tools_schema.py` (the tool schemas for the upstream
  tool ladder).
- `retain/fact_extraction.py`: the response-model/schema machinery
  (`_with_iso_timestamp_pattern`, `_with_optional_dimensions` model wrappers,
  `build_labels_model`, dynamic `LabelsFact` schema), chunk *splitting*
  iterators (rustsight has its own token-based chunker), attachments beyond
  the prompt section, batch API plumbing, envelope-shape repair retries.
- `search/temporal_extraction.py` / `query_analyzer`: query-side parsing with
  no prompt content; rustsight's `temporal.rs` covers its window parsing.
- Upstream's `llm_supports_string_pattern` flag: schema-only upstream, never
  changes prompt text.

## Faithfully preserved quirks

- Custom extraction instructions and the `build_final_system_prompt` mission
  keep their braces **doubled** in final output (upstream escapes for
  `str.format`; substituted values are not unescaped). Upstream's own
  `test_prompt_brace_escape.py` passes only because `{{x}}` contains `{x}` as
  a substring; the parity fixtures pin the doubled bytes.
- Consolidation mission/capacity text keeps single braces (it is embedded in
  a template that is `.format()`ed as a whole upstream) — also pinned by
  fixtures.
